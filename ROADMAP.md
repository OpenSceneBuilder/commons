# Building the OSB home

## 1. Establish the home

Create the organization, public profile and commons. Establish a private place for operating decisions, access records and recovery instructions.

Done when a new visitor can understand the purpose, find the steward and propose a bounded contribution.

## 2. Prepare one workshop

Select one pilot project. Confirm its authoritative source, maintainer, intended audience, rights, license, supported environment and setup steps before any migration or publication.

Done when an authorized contributor can reproduce a useful example from a fresh checkout using synthetic data.

## 3. Make collaboration dependable

Agree project checks, reviews, release ownership and how decisions are recorded. Apply the platform protections supported by the chosen plan.

Done when a contributor can submit a change and a maintainer can review, verify and integrate it. Repository settings must be checked directly; guidance files alone do not enforce them.

## 4. Prove continuity

Choose a backup schedule from acceptable loss and recovery time. Include source history, large files, release artifacts and operational records.

Done when a pilot can be restored into a separate location and used successfully. A backup existing is not a restoration test.

## 5. Welcome the first cohort

Invite a small group with named hosts, meaningful tasks and clear review arrangements. Fix the friction they encounter before expanding.

Done when the first contributor journey works from arrival through review and credit.

These are milestones, not promised dates. Project incubation, software capability and public release decisions remain separate.
